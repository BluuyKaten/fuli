# 股票复盘系统 - 开发进度

## 技术栈

- **后端**: Spring Boot 4.1.0 + Spring Cloud 2025.1.2 + Spring Cloud Alibaba 2025.1.0.0
- **ORM**: MyBatis-Plus 3.5.17 (`mybatis-plus-spring-boot4-starter`)
- **认证**: JJWT 0.13.0 (JWT, HMAC-SHA256, secret >= 256 bits)
- **数据库**: MySQL (每个服务独立数据库)
- **前端**: Vue 3 + Vite + TypeScript + Ant Design Vue + ECharts
- **服务注册**: Nacos (可选，不运行时不影响本地开发)

## 项目结构

```
fuli/
├── common-api/          # 公共模块 (Result, 异常, 实体基类)
├── gateway-service/     # 网关服务 (端口 8080)
├── auth-service/        # 认证服务 (端口 8081, 数据库 auth_db)
├── trade-service/       # 交易服务 (端口 8082, 数据库 trade_db)
├── analysis-service/    # 分析服务 (端口 8083，通过 Feign 读取交易与行情)
├── data-service/        # 数据同步服务 (端口 8084, 数据库 data_db)
├── frontend/            # 前端项目 (端口 3000)
└── sql/                 # 数据库脚本
    ├── auth_db.sql
    ├── trade_db.sql
    └── data_db.sql
```

## 服务间通信

trade-service 通过 Feign 调用 auth-service 的现金操作接口：

```java
@FeignClient(name = "auth-service")
public interface AuthFeignClient {
    @PutMapping("/auth/internal/deductCash")
    Result deductCash(@RequestParam Long userId, @RequestParam BigDecimal amount);

    @PutMapping("/auth/internal/addCash")
    Result addCash(@RequestParam Long userId, @RequestParam BigDecimal amount);
}
```

## 注意事项

1. **Spring Boot 4.x 变更**:
   - 移除 `bootstrap.yml`，改用 `spring.config.import=optional:nacos:`
   - 使用 `mybatis-plus-spring-boot4-starter`

2. **JWT Secret**: 必须 >= 32 字节 (256 bits)，通过环境变量 `JWT_SECRET` 配置

3. **Nacos**: local profile 禁用发现与配置中心，并为网关和 Feign 提供 localhost 直连地址；默认 profile 使用服务发现

4. **股票数据**: 需要预先导入 `stock_daily_data` 表数据

5. **环境变量**: 敏感配置（JWT_SECRET、DB_PASSWORD、INTERNAL_KEY）通过环境变量或 `.env` 文件配置，参见 `.env.example`

## 启动方式

### 方式一：Windows 本地启动（无需 Docker、无需 Nacos）

**前置条件**：
- 安装 [MySQL 8.0+](https://dev.mysql.com/downloads/installer/)（必须）
- 安装 JDK 21+
- 安装 Maven 3.8+
- 安装 Node.js 18+
- Redis（可选，用于 JWT 黑名单）

**步骤**：

```bash
# 1. 初始化数据库
# 打开 MySQL 命令行或 MySQL Workbench，执行：
source sql/auth_db.sql
source sql/trade_db.sql
source sql/data_db.sql
source sql/migrations/V2__lightweight_charts.sql

# 2. 设置环境变量（PowerShell）
# 注意：JWT_SECRET 必须 >= 32 字节，INTERNAL_KEY 必须 >= 16 字节。
# 下面给出的是本地开发用随机密钥（请勿用于生产）。
$env:JWT_SECRET="dev-only-jwt-secret-key-please-replace-in-production-0123456789"
$env:DB_USERNAME="root"
$env:DB_PASSWORD="123456"
$env:INTERNAL_KEY="dev-only-internal-key-0123456789"

# 3. 启动后端服务（按顺序，每个服务一个终端）
# 先在根目录安装公共模块，再分别启用 local profile；无需 Nacos。
mvn clean install -DskipTests
mvn -pl auth-service spring-boot:run -Dspring-boot.run.profiles=local
mvn -pl trade-service spring-boot:run -Dspring-boot.run.profiles=local
mvn -pl analysis-service spring-boot:run -Dspring-boot.run.profiles=local
mvn -pl data-service spring-boot:run -Dspring-boot.run.profiles=local
mvn -pl gateway-service spring-boot:run -Dspring-boot.run.profiles=local

# 4. 启动前端（新终端）
cd frontend
npm install
npm run dev
```

### 方式二：使用 Nacos（可选）

如果你希望使用服务注册中心（可选）：

1. 下载 [Nacos](https://github.com/alibaba/nacos/releases)
2. 启动 Nacos：`startup.cmd -m standalone`（Windows）
3. 不启用 local profile，设置各服务一致的 `JWT_SECRET`、`INTERNAL_KEY`，按需配置 `NACOS_SERVER`；网关和 Feign 使用服务发现

### 方式三：Docker Compose（可选）

```bash
docker-compose up -d
```

## Windows 常见问题

### 1. 端口被占用

```powershell
# 查看占用端口的进程
netstat -ano | findstr "8080"
# 终止任务
taskkill /PID <pid> /F
```

### 2. MySQL 连接失败

确认 MySQL 服务已启动：
```powershell
net start MySQL80
```

### 3. 环境变量不生效

PowerShell 中设置的环境变量仅在当前会话有效。永久设置：
```powershell
[Environment]::SetEnvironmentVariable("JWT_SECRET", "your-secret", "User")
```

或编辑 `.env` 文件（需要手动在代码中读取，或使用 `dotenv` 库）。

### 4. Nacos 启动失败

Nacos 是可选的。不启动时请启用 local profile，禁用注册与配置中心并使用直连地址。
如需启动 Nacos，可下载 [Nacos Windows 版](https://github.com/alibaba/nacos/releases)：
```bash
startup.cmd -m standalone
```

## 2026-11-10 增量：前端建议单确认页（阶段 3 收尾）

- [x] **建议单确认页**（`frontend/src/views/okx/OkxSuggestionsPage.vue`，路由 `/okx/suggestions`）：状态筛选（待确认/已执行/全部）+ 30 秒自动刷新（执行中自动跳过）+ 人工确认弹窗（标的/方向/类型/数量/价格/理由逐项核对）+ 调 `POST /data/okx/suggestions/{id}/execute`。执行失败时弹窗关闭、状态不变，可重试。
- [x] **修复 V11 遗留的状态机 bug**（`sql/migrations/V15__okx_suggestion_status_executed.sql`）：表约束 `chk_okx_suggestion_status` 只允许 `new/accepted/rejected/expired`，而 `OkxSuggestionExecutionService` 写的是 `executed`。MySQL 8.0.16+ **强制**执行 CHECK，于是「委托已报到 OKX、状态更新却抛 ERROR 3819」——建议单卡在 `new`、接口报错、用户以为没下成而重试。V15 把 `executed` 纳入状态机并去掉从未使用的 `accepted`（与 executed 语义重叠）。已实测：executed 可写、非法值仍被拦、脚本可重复执行。
- [x] **403 提示透出后端原因**：`request.ts` 原先把所有 403 统一显示成「没有权限访问」，把「未授予 OKX 交易权限」「服务账号不允许写操作」这类关键信息吞掉了。
