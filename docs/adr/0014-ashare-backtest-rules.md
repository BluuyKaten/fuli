# ADR-0014：A 股回测规则 —— 成本与可成交性

- 状态：已接受（2026-11-11）
- 关联：ADR-0011（加密回测口径）、ADR-0002（窗口化加载）
- 依据：`docs/multi-market-rollout.md`「长期：策略回测框架（A 股/美股待接）」
- 落地：`backtest/matcher.py`（`ashare_config`）、`backtest/engine.py`、`backtest/run.py`

## 背景

回测引擎最初为加密设计（ADR-0011）：撮合只有「次根开盘 + 滑点 + 费率」，成本模型是
`成交额 × 费率`。直接拿它跑 A 股，会系统性高估收益，原因有三：

1. **最低佣金缺失。** 万分之 2.5 的费率下，1000 元的小单佣金只有 0.25 元；实际券商收 5 元起。
   小额分批建仓的策略，真实成本是模型算出来的 20 倍。
2. **印花税缺失。** A 股卖出收 0.05%，单向。高频策略的费用被低估近一半。
3. **涨跌停不可成交被忽略。** 一字板涨停买不进、跌停卖不掉。策略在回测里「买到」的涨停板，
   实盘根本排不上队——这是最容易被当成 alpha 的假信号。

## 决策

### 1. 成本项拆成「佣金（含最低）+ 印花税（仅卖出）+ 过户费（双向）」

```python
ashare_config()  # round_digits=2, taker_fee=0.00025, min_commission=5.0,
                 # sell_tax_rate=0.0005, transfer_fee_rate=0.00001, price_limit_pct=0.10
```

`_fee()` 的算法：

```
买入 = max(成交额 × 费率, 最低佣金) + 成交额 × 过户费率
卖出 = max(成交额 × 费率, 最低佣金) + 成交额 × (过户费率 + 印花税率)
```

为什么把「最低佣金」单独建模而不是折进费率：它是个**分段函数**，交易额越小影响越大。
折进费率会变成「大单被多收、小单被少收」，两种错叠加后净值曲线看着还行、单笔归因全错。

`round_digits=2`：A 股以分为最小单位。加密仍用 8 位，两者互不影响。

### 2. 涨跌停只建模「一字板不可成交」，取保守侧

开盘价已触及涨停 → 买单拒绝；已触及跌停 → 卖单拒绝。涨跌停价按
`round(前收盘 × (1±pct), 精度)` 算，与交易所口径一致。

**不做**「涨停但可以排队成交」的乐观假设：真实市场里涨停买不买得到取决于排队位置和封单量，
无法从日线数据推断。宁可低估收益，也不要在回测里制造不存在的成交。

`pct` 参数化：主板 0.10、创业板/科创板 0.20、ST 0.05、北交所 0.30。

### 3. 一手 100 股由引擎的 `lot_size` 承担，不进 Matcher

`--market ashare` 时 `lot_size=100`，`_floor_to_lot` 会把买入量向下取整到 100 的倍数。
这带来一个真实约束：**10 万本金买不起一手茅台**（1400 元/股 × 100），回测会 0 成交。
这不是 bug，是 A 股的现实。回测报告里「0 笔成交」比「买了 70 股」诚实得多。

### 4. 拒单原因要能被统计，不能只返回「失败」

`FillOutcome.reason` 区分 `insufficient_cash` / `insufficient_position` / `limit_up` / `limit_down`。
`BacktestResult.limit_rejections` 单独计数，回测报告打印「涨跌停拒单 N 次」。

分开统计的理由：「钱不够」是资金管理问题，可以调参数解决；「一字板买不进」是市场约束，
策略无法规避。把两者混成一个「拒单数」，用户会去调一个调不好的参数。

### 5. 全部规则默认关闭，加密口径逐位不变

`MatcherConfig` 的新字段默认值都是「不生效」：`min_commission=0.0`（`max(x, 0)` 退化为 x）、
`price_limit_pct=0.0`（不判断）、税率 0。因此 ADR-0011 定下的加密回测结论不受影响——
这是硬约束，`CryptoCompatibilityTest` 用三个用例钉住。

## 后果

- A 股回测的费用量级回到真实水平。实测 000001.SZ（2020-06 ~ 2026-11，双均线）：
  A 股口径累计费用 **2418.82 元**，纯费率口径 654.98 元——差 3.7 倍。
- 一手 100 股让「资金不足」变成可见结果，而不是算出不存在的零股。
- 用户可以选择「不启用 A 股规则」（`--market crypto`）来看纯策略表现，
  两个结果的差额就是交易规则的代价。

## 已知限制

1. **前收盘用上一根 close 近似**，不是真实的 `bar.pre_close`。除权日两者不等，
   可能把除权跳空误判成跌停。建议 A 股回测用 `--adjust forward`（复权后序列连续，
   近似才成立）。彻底解法是让 `/market/bars` 输出 `preClose` 并给 `Bar` 加字段——
   `bar` 表里其实有这一列，只是没暴露到契约里。
2. **T+1 未显式建模**。日线粒度下天然满足（一天一根 bar，订单在次根开盘成交，
   当天没有第二次成交机会）。分钟线回测才会暴露这个问题，届时需要给 Matcher 记录当日买入量。
3. **ST 的 5%、北交所的 30% 要手工传** `--price-limit`。标的的板块信息在 `instrument` 表里，
   但没有映射到涨跌停幅度（ST 还会动态变化），暂不做自动推断。
4. **未建模停牌**：停牌日没有 bar，订单会被推迟到下一个有 bar 的交易日成交，
   这比「次日开盘」乐观一档。
5. **佣金率是固定值**，不区分券商/资金量档位；过户费沪深已统一，未按历史变更分段。
