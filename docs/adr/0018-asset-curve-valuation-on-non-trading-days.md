# ADR-0018：资产曲线在无行情日按「最近收盘价」估值，不再退回成本价

- 状态：已接受（2026-11-11）
- 关联：ADR-0017（资产曲线取数窗口）
- 落地：`analysis-service/.../AnalysisService#closeOnOrBefore`

## 背景

资产曲线的估值是「逐日 `现金 + Σ 持仓数量 × 当日收盘价`」。当日没有 K 线时，原实现
退化为**平均成本**：

```java
stockDailyPrices.get(code).getOrDefault(currentDate, avgCosts.get(code))
```

而循环是按**自然日**走的（`currentDate.plusDays(1)`，从首笔交易日一直走到今天）。
周末、节假日必然没有 K 线，于是每一个周末都会掉回成本、周一再弹回来。

不是推测，是改动前实现的真实输出（`AssetCurveFetchWindowTest` 的 fixture：
02-06 周五收 101300，02-09 周一 101900）：

```
[100500, 100100, 100500, 100700, 100900, 101100, 101300, 100100, 100100, 101900, 102100]
                                                  ↑周五     ↑周六  ↑周日
```

用户看到的是一张每周固定亏一次、周一又赚回来的锯齿图。盯久了会以为数据坏了，或者
以为自己每周都在亏。停牌股同样受害：停牌期间市值直接按买入成本计，浮盈浮亏被抹平。

## 决策

当天没有 K 线时，沿用该标的**最近一个已知收盘价**（`lastClose`）；只有连一根历史收盘价
都没有（例如当天建仓、当日又恰好无行情）才退回平均成本。

## 为什么不是「周末不出点」

另一个选项是只在有行情的日期往曲线里塞点。那样 `dates` 数组会变短（少掉约 2/7 的点），
前端虽然只是照单画图，但 `-24` 取「最近 24 个点」的迷你趋势线会跟着改变切片含义。
本次只修正数值、不动结构：点数不变，周末那两点变成与周五同高的平台。

这一条不影响交易日：有 K 线时仍按当日收盘价，逐点与改动前一致。

## 后果

- 资产曲线的周末/节假日/停牌日不再出现「掉回成本」的假下跌。
- **这是口径变更**：同一账户在改动前后，非交易日那几天的数字会不同（变大或变小取决于浮盈方向）。
  交易日数字不变。
- `docs/api.md` 里「缺行情时退化为平均成本」的描述已同步改为「最近一个已知收盘价」。
- 估值逻辑抽成了 `closeOnOrBefore`，`AssetCurveFetchWindowTest` 同时用它构造参照实现，
  避免测试与生产各写一份而漂移。
